# Visual refinement shared by design workflows

Use for substantial visual creation or redesign. For a small correction, inspect
the affected state and keep the loop small. The hosting skill owns its deliverable,
design system, domain rubric, and human checkpoints; this reference owns the review
loop. Do not add a second intake, approval gate, or competing aesthetic preset.

## Brief and direction

Reuse the audience, task, constraints, assets, and references already supplied.
Capture the intended feeling and what should make it memorable. Translate vague
preferences into visible qualities: composition, density, type, texture, imagery,
and interaction. Record what to avoid and why. References establish a quality bar;
extract useful qualities rather than copying another brand's identity.

When direction is open, use `divergent-ideation` for distinct concepts. Keep early
descriptions short, then render a representative viewport or state for promising
directions before spending on polish. Reuse the user's taste reactions to steer
the next version. Where selection is delegated, proceed with explicit assumptions
and a recommendation instead of inserting a new mandatory pause.

## Evidence before critique

Capture the actual built or generated result, with viewport and state identified.
Review the whole composition before details. A prompt or source code cannot prove
visual quality. Screenshots establish appearance, not working keyboard navigation,
responsive behavior between captures, or successful form submission.

When an independent critic is available and delegation is authorized, give it the
current screenshots, a compact brief, constraints, and relevant reference images.
Keep implementation effort, the implementer's rationale, earlier scores, and
desired approval score out of that review. Never remove constraints to make the
critique appear more independent. Use the configured model unless a change was
requested; no model-size or cost assumptions are needed for this protocol.

Without an independent critic, perform the same review inline and label it a
self-review. Do not claim fresh-context independence. The critic does not modify
files or grant release approval.

## Fix the most consequential gaps

Use the hosting skill's rubric. For each material finding record:

| Visible issue and location | Effect on the intended experience | Specific next change | Evidence needed |
|---|---|---|---|

Prioritize comprehension, task completion, hierarchy, distinctiveness, and execution
quality. Preserve strengths. Start with one or two iterations for a new direction,
then assess improvement before extending. Existing agreed scope or domain minimums
still apply. Fix the highest-impact few issues, recapture, and compare the same
states. If feedback oscillates or gains stop, report the unresolved trade-off and
recommend a decision or a different direction. A numerical taste score alone is
not a completion criterion; do not run an unbounded loop trying to raise it.

## Subtraction and media decisions

Before adding another surface, label, effect, or animation, try removing or merging
what competes with the primary task. Keep elements that convey information, afford
an action, establish necessary trust, or carry the chosen identity. Preserve help,
error messages, accessible names, and required disclosures even if visually quiet.
Compare the simplified version against the same brief; sparse is not always better.

Use supplied assets, authentic screenshots, or code-native graphics when those fit.
Use image generation for useful original bitmap assets, following the available
`imagegen` guidance. Generated concepts must not masquerade as customer evidence,
real product functionality, or authoritative identity assets. Typography-only work
can be complete. Missing decorative media is not a reason to leave a page unfinished.

Use motion to explain state, provide feedback, or support a particular narrative.
For generated video, test the loop seam, key transitions, loading, crop, and static
fallback. For interactive motion, check intermediate states as well as endpoints.
Respect reduced motion, page weight, and interaction performance. A successful
effect is optional unless the brief requires it; it is not proof of good UX.

## Completion and reusable learning

Verify representative desktop/mobile states, fonts, crops, contrast, overflow,
focus, and relevant interactions using appropriate tools. Resolve blocking defects
or report concrete limits. Keep a compact record in the project's existing design
notes: brief, references, candidate/seed if used, screenshot, feedback, change, and
remaining evidence. Preserve rejected experiments when useful for a future rerun;
do not save preferences into global memory without a user request.
